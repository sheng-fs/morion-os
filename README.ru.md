## Обзор

Morion OS — современная операционная система, написанная с нуля на **Rust**. Проект находится в **фазе перепроектирования и переписывания**: архитектурные конфликты ранних реализаций были заново тщательно проанализированы, и в качестве основного технического направления окончательно утверждена **гибридная архитектура «микроядро + экзоядро»**.

Устаревший код переведён в архив (ветка `legacy`), а основная ветка начата заново. С тех пор проект вышел за рамки чистого проектирования и превратился в **работающий прототип микроядра**: он загружается под QEMU (UEFI) в пользовательскую оболочку и обеспечивает полный путь чтения/записи файлов — «приложение → libvfs → служба файловой системы → служба блочных устройств → диск NVMe».

### Ключевые принципы

- **Доверенная вычислительная база микроядра**: ядро предоставляет единственную границу — интерфейс системных вызовов; файловые системы, сеть, драйверы устройств, графика, оболочка и все прочие традиционные функции ядра реализованы как пользовательские службы. В ядре остаётся лишь горстка ключевых примитивов (IPC, отображение адресных пространств, домены защиты, возможности) — и даже в полной таблице системных вызовов 0–63 они занимают лишь малую часть (см. [docs/dev-reference.md](./docs/dev-reference.md) §5).
- **Высокопроизводительный путь экзоядра**: механизм «Performance Enclave» и аппаратные возможности IOMMU / CHERI позволяют высокопроизводительным приложениям (игры, AI) работать с оборудованием напрямую — без переключений в ядро и без копирования данных.
- **Модель безопасности на основе возможностей**: отказ от традиционной системы прав UID/GID. Возможности служат единственным мандатом доступа, что принципиально устраняет уязвимость «root может всё».
- **Драйверы Anykernel с двумя режимами**: один и тот же исходный код драйвера компилируется либо в пользовательский служебный процесс (сценарий совместного использования), либо в библиотеку прямого доступа (высокопроизводительный сценарий), при этом более 90% кода общие.

> Подробное описание архитектуры: [docs/architecture.md](./docs/architecture.md).

## Текущее состояние

Система прошла путь от проектных документов до **прототипа микроядра, который загружается и работает на реальном оборудовании / QEMU**. В таблице ниже разделены «работающее» и «не начатое», чтобы проектные цели не принимались за существующие возможности.

| Область | Статус | Примечания |
|------|--------|-------|
| Ядро микроядра | ✅ Работает | Домены защиты, синхронный/асинхронный IPC, вытесняющее планирование (включая **блокировку с ограничением по времени**), адресные пространства и подкачка по требованию, маршрутизация прерываний (PIC + **LAPIC/MSI-X**, включая **блокирующее ожидание прерываний** и **многовекторный `wait_any`**), система возможностей (включая **передачу возможностей по IPC**) |
| Загрузка на реальном оборудовании / питание | ✅ Работает | UEFI-загрузчик находит загрузочный диск по Device Path загрузочного тома (`BootInfo` v5); **вариант `SAFE` предоставляет только контроллеры блочных устройств в цепочке загрузочного диска** (контроллеры USB никогда не отфильтровываются); команда оболочки `poweroff` использует ACPI S5 (FADT + DSDT `_S5`), `reboot` проходит цепочку i8042 → `0xCF9` → triple fault; при отсутствии контроллера PS/2 выдаётся явное сообщение |
| Интерфейс системных вызовов | ✅ 56 (ID 0–63) | Полная таблица ID ядра: [docs/dev-reference.md](./docs/dev-reference.md) §5; подмножество для приложений: [docs/app-dev-guide.md](./docs/app-dev-guide.md) §3 |
| Модель безопасности на основе возможностей | ✅ Работает | Слоты возможностей + **дескрипторы возможностей** (выдаются при открытии, проверяются перед каждой операцией ввода-вывода, отзываются при закрытии), по умолчанию — ноль возможностей; **передача дескриптора** (move) и **делегирование возможностей** (copy, без усиления) во время выполнения по IPC — не всё должно выделяться статически при загрузке |
| Пользовательские драйверы | ✅ Частично | Клавиатурный драйвер (IRQ1 / проверка наличия PS/2 + USB HID boot keyboard); служба блочных устройств (драйвер NVMe с резервным путём IDE PIO); **многоконтроллерный xHCI** (до 4 контроллеров, USB-накопители + USB HID-клавиатура); сетевой драйвер **`net_srv` (virtio-net, домен 16)** — драйвер N2/N3 работает (bring-up modern virtio: разбор virtio caps / чтение MAC / создание RX·TX virtqueue / `DRIVER_OK` / **RX по прерываниям MSI-X**, а на его собственный ARP-запрос отвечает шлюз `NET1 … ARP reply OK`). **Универсальное предоставление устройства (D1)**: ядро в `device.rs` выдаёт `DeviceGrant` (BAR + непрерывный блок DMA + параметры MSI-X, без семантики устройства); в ядре **больше нет кода, специфичного для NVMe** — раскладка очередей и протокол устройства живут в домене драйвера; драйвер также может сам разбирать PCI-возможности своего устройства через `SYS_DEVICE_CONFIG_READ`, а ядро отображает таблицу MSI-X из другого BAR согласно `BIR` |
| Пользовательские файловые системы | ✅ Частично | FAT32 (включая длинные имена VFAT), tmpfs, оригинальная MorionFS v2 (COW + снимки + битовая карта свободных блоков/освобождение пространства + косвенные блоки для больших файлов + записи каталога переменной длины/длинные имена + метаданные узлов + слой косвенности по inode-номерам/жёсткие ссылки/символьные ссылки + **форматирование с учётом геометрии тома** + **явная `mkfs.mfs`, несколько томов и переключение основного тома**), ext2 **только чтение**, exFAT (чтение + запись, большие тома с большим числом кластеров) |
| Слой разделов / томов | ✅ Работает | block_srv разбирает таблицу разделов **MBR/GPT** каждого диска в таблицу томов и определяет тип ФС по сигнатуре в начале тома; также умеет **записывать таблицы разделов** (`part.create/del/wipe/reload`: создание/удаление разделов, очистка, повторное чтение — и GPT, и MBR); `dev` теперь «номер тома», а блочный слой поддерживает многостраничный DMA (одна команда ≤ 128 KiB); **монтирование нескольких томов**: дополнительные тома того же типа автоматически монтируются в `/usb<vol>`, так что одна кодовая база обслуживает несколько дисков — это прокладывает путь к чтению реальных разделов USB |
| Оболочка и единое дерево каталогов | ✅ Работает | `help/echo/uname/version/pwd/ls/cat/run/wget/net/ping/ping6/dns/wifi/lspci/dmesg/cd/mkdir/touch/rm/mv/ln/ln -s/chmod/chown/truncate/stat/lstat/readlink/mkfs.mfs/mfs.primary/mfs.snap/mfs.snaps/mfs.rollback/mfs.gc/mfs.fsck/mfs.sync/df/part.create/part.del/part.wipe/part.reload/clear/poweroff/reboot` (`ls -l` в длинном формате, символьные ссылки показываются как `l`; `dmesg` поддерживает `-d/-a/-g/path` и `Ctrl+C`; `uname`/`version` сообщают строку версии через `SYS_UNAME`); несколько файловых систем собираются слоем монтирования в единый корень `/`, поддерживается монтирование во время выполнения |
| Графика / GUI | 🚧 В работе | **G1** — фреймбуфер передан пользовательской `gfx_srv` (домен 15) эксклюзивно: добавлены `Capability::Fb` + `SYS_FB_INFO/MAP/TAKEOVER`; после захвата терминал ядра больше не пишет на экран (вывод остаётся только на COM1). **G2** — примитивы рисования `fill/rect/blit` + разделяемые поверхности + клиентская библиотека `libmorion::gfx`; `blit` перечитывает фреймбуфер и проверяет результат перед ответом (самотест GS-1). **G3a** — рендеринг текста вынесен наружу: шрифт (ASCII 8×16 + CJK 16×16 `cjk.bin` ≈276 KB) и состояние терминала переезжают из ядра в `gfx/`, новый протокол `GFX_OP_TEXT/CLEAR/MOVE/QUERY`, попиксельная проверка «запись-затем-чтение» (самотест GT-1). **G3b** — вывод оболочки на экране: `SYS_CONSOLE_READY(47)`; приёмник печати `sink()` в `libmorion` может **зеркалировать** вывод на экранную консоль для каждого процесса (включает только оболочка). **G3c** — ядро избавляется от шрифта CJK (−276 KB, ELF ядра 347 KB → 69 KB); терминал ядра деградирует до ASCII + tofu, рендеринг CJK происходит только в пользовательском пространстве. **G4** — ввод вынесен из ядра: очередь байтов клавиш `SYS_KEY_PUSH(48)/SYS_KEY_READ(49)` (ядро только пересылает байты), редактирование строки/эхо в клиентской библиотеке `morion::console::readline`. **G6** — самовосстановление служб: `ipc::call` больше не висит вечно (тайм-аут + быстрый отказ, если у цели нет живой задачи), фреймбуфер зарегистрирован как зарезервированный диапазон ядра, устаревшие запросы в почтовом ящике отбрасываются при перезапуске, клиент пересоздаёт разделяемые сеансы, `gfx_srv` контролируется init (самотест GS-2). Текстовая консоль ядра остаётся только для вывода при загрузке и panic |
| Сеть / виртуализация / анклавы / менеджер пакетов | 🚧 В работе | **Сеть**: драйвер `net_srv` virtio-net работает; стек выделен в отдельный `netstack_srv` (домен 21: TCP/IP + служба сокетов + контроль доступа к портам через возможности), со второй/третьей реальными сетевыми картами `e1000e_srv`(22) / `e1000_srv`(24), беспроводной `wifi_srv`(25) и `httpd_srv`(23) внутри гостя. **Анклавы**: аппаратная изоляция IOMMU/VT-d выполнена (с E1c окно целевого устройства ограничено, а DMA за его пределами отвергается с доказательствами); менеджер анклавов E2/E3 не сделан. **Виртуализация и менеджер пакетов**: проект решён, реализации пока нет |
| Интерфейс возможностей для системного AI | 📐 Спецификация определена | Как приложение предоставляет функциональность системному AI: [docs/app-dev-guide.md](./docs/app-dev-guide.md) §9 |

## Версия

Текущая версия **`0.4.0`**; выпущенный вариант без графики помечен тегом **`v0.4.0-nogui`**.

- **Единственный источник истины** для констант версии — `kernel/src/version.rs` (`SYSTEM_NAME` / `VERSION` / `MACHINE` / `VARIANT` / `BUILD`), передаваемый в пользовательское пространство через `SYS_UNAME(51)` — команды оболочки `uname` / `version` читают его (номер сборки — сокращённый git-хеш, внедряемый `Makefile`).
- Два варианта сборки:
  - **Обычный (с графикой)**: `make ...`; вывод оболочки дополнительно **зеркалируется** на экранную консоль `gfx_srv`.
  - **Без графики**: `make NOGUI=1 ...`; оболочка не включает зеркалирование на экран (ввод/эхо идут через последовательный порт), строка релиза сообщает `0.4.0-nogui`, артефакты размещаются в `build/nogui/`. Остальные службы и полный базовый набор регрессионных тестов не изменяются.
- История изменений — в [CHANGELOG.md](./CHANGELOG.md).

## Основы проектирования

### Примитивы микроядра

Содержит только несократимый минимальный набор:

| Примитив | Описание |
|-----------|-------------|
| `send` / `receive` / `call` | Синхронный/асинхронный IPC с передачей возможностей |
| `map` / `unmap` | Управление отображением адресного пространства |
| `create_domain` / `destroy_domain` | Жизненный цикл домена защиты (процесса) |
| `schedule` | Планирование CPU |
| `allocate_frame` / `free_frame` | Управление физическими кадрами памяти |
| `register_interrupt` / `ack_interrupt` | Авторизация и подтверждение прерываний |
| `create_enclave` | Создание аппаратно изолированного анклава |

### Внешний пейджер

- Ядро только перехватывает и перенаправляет страничные ошибки; пользовательские службы пейджера определяют содержимое страниц и политику замещения
- Каждый процесс может назначить выделенный пейджер — подкачка по требованию, сжатые пулы памяти, сетевое хранилище и т. д.

### Драйверы Anykernel с двумя режимами

| Режим | Назначение | Характеристики |
|------|--------|-----------------|
| **Процесс-служба драйвера** | Общие приложения | Совместное использование устройства, безопасная изоляция, косвенный доступ через IPC |
| **Библиотека драйвера прямого доступа (LibDevice)** | Игры / AI | Компоновка во время выполнения, нулевые переключения в ядро для операций MMIO/DMA |

Единый интерфейс Rust trait, выбор бэкенда через feature-флаги времени компиляции, >90% общего кода.

### Анклав производительности

1. IOMMU отображает MMIO и DMA-окна устройства в адресное пространство процесса
2. Подключается библиотека прямого драйвера LibDevice
3. Команды GPU/NPU отправляются напрямую без вмешательства ядра

Радиус поражения аппаратно ограничен ресурсными границами анклава.

### Модель безопасности на основе возможностей

- Возможности — единственный мандат доступа, без зависимости от UID/GID
- Новые процессы стартуют с нулевым набором возможностей; их явно предоставляет родитель
- POSIX-API прав доступа (`chmod`/`chown`) транслируются libc в операции с возможностями
- Политику безопасности интерпретирует пользовательский движок политик, поддерживаются динамические обновления

### Пользовательские службы

Вся традиционная функциональность ядра работает как независимые пользовательские процессы:

| Служба | Ответственность | Статус |
|---------|---------------|--------|
| Служба файловых систем | FAT32 (включая длинные имена VFAT), tmpfs, оригинальная MorionFS, ext2 только чтение, exFAT (чтение + запись), унифицированы через libvfs | ✅ Реализовано (ext2 только чтение / exFAT чтение-запись) |
| Служба устройств | Блочное устройство (драйвер NVMe), клавиатурный драйвер, диспетчеризация прерываний | ✅ Частично |
| Служба оболочки | Интерпретатор командной строки + единое дерево каталогов / монтирование во время выполнения | ✅ Реализовано |
| Сетевой стек | Пользовательский TCP/IP, разделяемая память без копирования | ⏳ Запланировано |
| Безопасность / аудит | Аутентификация, движок политик, обнаружение вторжений | ⏳ Запланировано |
| Менеджер анклавов | Жизненный цикл анклавов, потоки журналов, миграция и приостановка | ⏳ Запланировано |
| Менеджер пакетов | Декларативные сборки в стиле Nix, атомарное переключение, откат версий | ⏳ Запланировано |
| Служба GUI | Акриловый полупрозрачный рабочий стол, широкая настраиваемость (фреймбуфер `gfx_srv` / текстовая консоль / примитивы рисования реализованы, среда рабочего стола не начата) | 🚧 В работе |
| Аудио / IME / контейнеры / время / питание / журналирование / конфигурация | Инфраструктурные службы системы | ⏳ Запланировано |
| Регистрация возможностей AI / шлюзовая служба | Регистрация и обнаружение возможностей приложений, авторизация и аудит вызовов AI | 📐 Спецификация определена (см. [app-dev-guide.md](./docs/app-dev-guide.md) §9) |

### Виртуализация

- Микроядро также выполняет роль гипервизора (Intel VT-x / AMD-V)
- Поддерживает unikernel'ы и немодифицированных гостей Linux/Windows
- Проброс PCIe-устройств (VT-d / IOMMU), вложенные анклавы

### Загрузка

- Нативный UEFI, без переходов в legacy real mode
- Загрузочное меню GOP высокого разрешения, акриловая тема
- Загрузочные записи на основе замыканий Nix, атомарное переключение и откат
- Измерения TPM 2.0 + проверка Secure Boot
- Тёплая перезагрузка через kexec, сосуществование нескольких ОС

## Структура репозитория

### Текущая структура

Проект представляет собой Rust workspace (корневой `Cargo.toml`), который сейчас содержит крейты `boot`, `kernel`, `user/srv`, `user/libmorion`, `user/libdevice`, `user/hello` и `kernel_test`. Каждая системная служба вне ядра (блочные устройства / файловые системы / монтирование / оболочка / клавиатурный драйвер, …) — **отдельная пользовательская программа** (один `[[bin]]` на службу в `user/srv` → один самостоятельный ELF); **загрузчик читает их из ESP (`EFI/morion/services/`) при загрузке** и передаёт ядру через таблицу модулей `BootInfo`, после чего ядро загружает каждую в её фиксированный домен (E2b: больше не единый плоский бинарник, диспетчеризуемый по id домена; E3b: службы больше не встраиваются в образ ядра). UI-ресурсы организованы по назначению: ресурсы времени загрузки в `boot/loader/resources/`, системные ресурсы в `resources/system/`.

## План развития

> Подробный план по файловым системам: [docs/roadmap-fs.md](./docs/roadmap-fs.md); план по графической подсистеме: [docs/roadmap-gfx.md](./docs/roadmap-gfx.md). Отмеченные пункты **проверены в работе под QEMU**.

### Фаза 1 — Ядро микроядра (в основном завершена)

- [x] Создание доменов защиты (процессов) и изоляция адресных пространств
- [x] Синхронный/асинхронный IPC (`send` / `recv` / `call` / `reply`; полезная нагрузка 96 байт + разделяемая память для больших объёмов данных)
- [x] Планирование задач и переключение контекста
- [x] map/unmap адресного пространства + пользовательский пейджер (подкачка по требованию)
- [x] Маршрутизация прерываний («прерывания как IPC») + предоставление MMIO / портов ввода-вывода
- [x] Система возможностей (слоты + дескрипторы: выдача / проверка / отзыв)
- [x] **Передача возможностей по IPC** (передача дескриптора `SYS_HANDLE_SEND`: переместить открытый объект **в** целевой домен, семантика move; делегирование возможностей `SYS_CAP_SEND`: **копировать** удерживаемую возможность, без усиления; оба требуют `SendTo(to)`). Домены 0/1/3 покрывают 8 положительных/отрицательных случаев самотестирования при загрузке

### Фаза 2 — Базовые службы (в работе)

- [x] Перечисление PCI + пользовательский драйвер NVMe (служба блочных устройств с резервным путём IDE PIO)
- [x] **Разбор разделов MBR/GPT + слой томов** (внутри block_srv, `dev` = номер тома; тип ФС определяется по сигнатуре в начале тома)
- [x] **Монтирование нескольких томов**: старшие 32 бита тега запроса несут код тома, один open привязывает один том; каждая служба ФС автоматически сообщает о своих дополнительных томах (монтируются в `/usb<vol>`); буфер кластера fat32 2 → 16 страниц (потолок кластера **64 KiB**), лимит групп блоков ext2 16 → 4096
- [x] Файловые системы: FAT32 (включая длинные имена VFAT) / tmpfs / оригинальная MorionFS (COW + снимки)
- [x] Совместимость с ext2 **только чтение** (монтирует существующие разделы Linux)
- [x] Совместимость с exFAT (`exfat_srv` домен 13, монтируется в `/usb`): **только чтение** + **чтение-запись** (`CREAT/WRITE/MKDIR/UNLINK/RMDIR/TRUNCATE`) + **большие тома** (многостраничный DMA, одна команда ≤ 128 KiB)
- [x] libvfs + слой монтирования: несколько файловых систем собираются в единый корень `/`, поддерживается монтирование во время выполнения
- [x] Оболочка (встроенные команды + пути относительно cwd) и пользовательский клавиатурный драйвер
- [x] **Формат MorionFS v2 финализирован + освобождение пространства / GC** (битовая карта свободных блоков + mark & sweep)
- [x] **Большие файлы MorionFS** (`MFS3`: косвенные блоки, преодоление старого лимита ≈4 MiB)
- [x] **Каталоги и длинные имена MorionFS** (`MFS4`: записи каталога переменной длины + блоки расширения, имена ≤255 байт)
- [x] **Метаданные узлов MorionFS** (`MFS5`: временные метки / права / владелец / число ссылок, `rename` / `truncate` / `chmod`)
- [x] **Косвенность по inode-номерам + жёсткие ссылки MorionFS** (`MFS6`)
- [x] **Символьные ссылки MorionFS** (`MFSL`: разрешение пути с переходом по ссылке + защита от циклов, `readlink` / `lstat` / `ln -s`)
- [x] **Форматирование MorionFS с учётом геометрии тома** (**M7**)
- [x] **Явное форматирование MorionFS + несколько томов** (**M8 / S2**: `mkfs.mfs <vol>`, проверка допускает только пустые тома или тома MFS)
- [x] **Масштабирование ёмкости MorionFS (битовая карта вынесена)** (**S3a**: потолок ёмкости ≈119 MiB → **≈127.25 GiB**)
- [x] **Отдельный файл MorionFS больше 4 GiB** (**S3b**: VFS `offset`/`size` u64 сквозным образом + косвенный блок третьего уровня `MFI3`)
- [x] **Переключение основного тома MorionFS** (**S2**: суперблок хранит серийный номер основного тома; побеждает наибольший серийный номер)
- [x] **Переназначение основного тома MorionFS только маркером** (**S2**: `mfs.primary <vol>` без изменения данных)
- [x] **Использование пространства `df`** (MorionFS сообщает всего / занято / свободно)
- [x] **Завершение управления томами: запись таблиц разделов** (**S2**: `part.create/del/wipe/reload`, GPT + MBR, проверено на хосте через `sgdisk -v`)
- [x] **Прерывания NVMe (MSI/MSI-X)** (**S3**: минимальная поддержка LAPIC + обход PCI-возможностей + сегмент векторов MSI `0x50..0x5F`)
- [x] **Блокирующее ожидание прерывания (примитив wait)** (**S4**: блокировка с ограничением по времени + `SYS_IRQ_WAIT`)
- [x] **Несколько векторов + `wait_any`** (**S5**: ключ ожидания на домен + маска векторов, admin + 2 очереди I/O, каждая со своим вектором)
- [x] **Рендеринг CJK в терминале (CJK / полноширинный / смешанная ширина)** (позднее удалён со стороны ядра в G3c, шрифт перенесён в пользовательскую `gfx_srv`)

- [x] **Пользовательский рантайм libmorion + команда `run`** (**E2a**)
- [x] **Разделение служб на самостоятельные программы + уничтожение домена / освобождение кадров** (**E2b**: 14 служб, по одному ELF; `SYS_DOMAIN_DESTROY/COUNT/FRAME_FREE`)
- [x] **Завершение жизненного цикла служб** (**E3a/E3b/E3c**: W^X пользовательских страниц; службы вынесены из образа ядра; супервизор `init` + перезапуск на месте из образа в памяти, без зависимости от диска)
- [x] **Графика G1 (фреймбуфер перенесён в пользовательское пространство)**
- [x] **Графика G2 (примитивы рисования + разделяемые поверхности + `libmorion::gfx`)**
- [x] **Графика G3a (терминал в службе + рендеринг текста вынесены)**
